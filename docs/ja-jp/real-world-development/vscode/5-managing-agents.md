GitHub Copilot をエージェントモードにすると、コードベースを調べ、変更を提案し、ファイルを編集してコマンドを実行します。VS Code の Copilot Chat は、作業をリアルタイムに確認できるため、すべてのツール呼び出しやファイルの編集を追跡できます。差分をインラインでレビューし、個々の変更を採用または取り消し、エディターを離れずに追加のプロンプトを送って作業を調整または拡張できます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして採用します。
- 作業中のセッションに指示を送り、ハイコントラストモードに加えてライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントが、ハイコントラストモードを実装しています。作業中、デザインチームから新たな依頼がありました。デフォルトテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加してほしいとのことです。新しい会話を最初から始める代わりに、既存のセッションに指示を送り、作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各ステップ、調査したファイル、実行したコマンド、提案する編集が表示されます。ファイル編集は差分と **Keep**/**Undo** 操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求められたターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャット内に表示されます。
   - **Keep** を選択すると変更を採用します。
   - **Undo** を選択すると変更を取り消し、エージェントに別の方法を試させます。
4. チャット上部の **Files changed** を開くと、このセッション中にエージェントが編集したファイルをすべて確認できます。

> [!NOTE]
> ターミナルコマンドの実行などに許可が必要な場合、エージェントは一時停止して **Allow** を表示します。実行してもよいコマンドだけを許可してください。

5. エージェントがハイコントラストモードの実装を完了するまで待ちます。最後に、変更内容の概要が表示されます。

## エージェントにライトモードを追加するよう指示する

ハイコントラストモードができたら、同じ会話でライトモードの切り替えを追加します。同じチャットセッションを続けるため、エージェントは前の作業のコンテキスト (変更したコンポーネント、使用したスタイル、設定したローカルストレージのパターンなど) を保持しています。

1. Copilot Chat の入力欄に次のプロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは既存の変更を確認し、ライトモードの追加を提案します。
3. ハイコントラストモードのときと同じように、新しい編集を確認します。差分ごとに **Keep** または **Undo** を選択します。
4. エージェントの進め方が希望と異なる場合 (たとえば、切り替え UI を意図しない方法でリファクタリングする場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、補足のプロンプトを送信します。

> [!TIP]
> 作業中のセッションに指示を送るほうが、最初からやり直すよりも速く進められます。追加のプロンプトを使って、調整を依頼できます (「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う」)、方針を修正できます (「切り替えを 3 つにせず、ライトモードを既存の設定パネルに追加する」)、範囲を広げることもできます (「両方の切り替えにキーボードショートカットも追加する」)。

## 変更されたファイルをレビューする

作業をコミットする前に、エージェントが変更したすべてのファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧全体を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントのアクセシビリティパターン (ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージによる設定の保存など) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使い、進行中のセッションを監視して方向付けしました。ファイルの編集を確認し、変更を採用または取り消し、コンテキストを保ったまま追加のプロンプトで作業を拡張しました。

このレッスンでは、次のことを学びました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を採用または取り消す。
- 作業中のセッションに追加のプロンプトを送り、方向付けする。

[次のレッスン][next-lesson]では、アクセシビリティの作業をプルリクエストとして公開し、このラボを通じてローカルのカスタムエージェントが生成した変更をレビューします。
